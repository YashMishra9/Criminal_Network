## 1. Task ID and Title

**A1 — FastAPI App Skeleton**

## 2. Track

Track A (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Stand up the FastAPI application entrypoint with router registration stubs for all eight DOC3 §12 endpoint groups (entities, graph, analytics, patterns, evidence, ask, cases, ingestion).

## 4. Why This Task Exists

Every other backend track needs a running app to register routes against. This is the first thing that must exist.

## 5. Dependencies

none

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC2 §2.2 (monolith rationale)
- DOC3 §12 (full endpoint list)

## 7. Inputs

- DOC3 §12 endpoint list

## 8. Expected Outputs

- A running FastAPI app with 8 registered (stub) routers, prefixed /api/v1

## 9. Files/Modules to Create or Modify

- backend/app/main.py
- backend/app/api/entities.py
- backend/app/api/graph.py
- backend/app/api/analytics.py
- backend/app/api/patterns.py
- backend/app/api/evidence.py
- backend/app/api/ask.py
- backend/app/api/cases.py
- backend/app/api/ingestion.py

## 10. Exact Interfaces/Contracts to Follow

- Router prefix: /api/v1
- One router module per DOC3 §12 group, matching its section numbering exactly (12.1-12.3 -> entities.py, 12.4 -> graph.py, 12.5 -> analytics.py, 12.6 -> patterns.py, 12.7 -> evidence.py, 12.8 -> ask.py, 12.9 -> cases.py, 12.10 -> ingestion.py)

## 11. Implementation Requirements

- Create the FastAPI() app instance in main.py.
- Register one APIRouter per group listed above, with the correct URL prefix.
- Each stub route handler returns a clear 'not implemented' placeholder (e.g., HTTP 501) — no business logic belongs in this task.
- Leave clear TODO markers pointing to the owning task for each router's real implementation (C6, D5, F4, G3, B4-adjacent for ingestion).

## 12. Acceptance Criteria

- The app starts without error.
- Every one of the 8 router groups is registered and reachable at its documented path prefix.
- No route in this task contains real business logic.

## 13. Tests Required

- A TestClient-based test that starts the app and confirms all 8 routers are mounted.
- A test hitting each stub route and confirming it responds (even if with a placeholder status) rather than crashing.

## 14. Definition of Done

uvicorn runs the app locally; all 8 router groups are registered and independently reachable.

## 15. Parallelization Information

Fully parallel with A2-A6, H1, H2, E1. Nothing in Track A blocks on A1 except A6 (which registers exception handlers onto this app).

## 16. Integration / Sync Point

Contributes to Sync 1 (A-ready).

## 17. Explicit Constraints — Things This Task Must NOT Do

- Do not implement any business logic in the stub handlers.
- Do not add any endpoint not listed in DOC3 §12.
- Do not change the /api/v1 path convention or invent alternate route groupings.
