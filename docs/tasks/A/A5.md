## 1. Task ID and Title

**A5 — LLMClient Interface & Degradation Handling**

## 2. Track

Track A (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement the LLMClient.generate() interface with timeout, single-retry, and typed-failure behavior per DOC3 §14.

## 4. Why This Task Exists

This is the single choke point DOC2 §12A relies on for consistent LLM degradation across Extraction (B6), Ask-the-Network (F1/F3), and Case Workspace (G2).

## 5. Dependencies

A2

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §14 (LLM Interface Contract, full)
- DOC2 §12A (LLM Degradation Model)

## 7. Inputs

- Config (LLM provider/API key) from A2

## 8. Expected Outputs

- An LLMClient with generate(prompt, context, options?) -> LLMResult

## 9. Files/Modules to Create or Modify

- backend/app/llm/client.py

## 10. Exact Interfaces/Contracts to Follow

- generate(prompt: str, context: object, options?: {timeout_ms?: number}) -> LLMResult
- LLMResult = {status: 'ok', text: string} | {status: 'unavailable', reason: 'timeout'|'provider_error'|'rate_limited'}

## 11. Implementation Requirements

- Implement timeout handling with a single retry before returning an unavailable result — never retry indefinitely.
- generate() must never raise an uncaught exception to the caller — always return a typed LLMResult.
- The concrete provider (model, endpoint, credentials) is resolved entirely inside this module via config — no other module may reference provider-specific details (DOC3 §14 contract rule).
- Every call site must pass context explicitly; do not rely on implicit/global state.

## 12. Acceptance Criteria

- Calling generate() against a deliberately unreachable/misconfigured provider returns {status: 'unavailable', reason: ...} and never throws.
- A successful call returns {status: 'ok', text: ...}.

## 13. Tests Required

- Unit tests with a mocked provider simulating: success, timeout, provider_error, rate_limited.
- A test confirming no exception propagates out of generate() under any simulated failure.

## 14. Definition of Done

LLMClient is importable and behaviorally correct per DOC2 §12A for all three eventual callers (B6, F1/F3, G2), even though none of them exist yet.

## 17. Explicit Constraints — Things This Task Must NOT Do

- Do not let any future caller bypass this interface to call a provider directly.
