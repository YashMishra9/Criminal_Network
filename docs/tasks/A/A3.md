## 1. Task ID and Title

**A3 — Shared Contract Types**

## 2. Track

Track A (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement every DOC3 §1 data model (RawRecord through AnalyticsResult, including the §1.13 ID-scope implications) as a pydantic model, matching field names, types, and nullability exactly.

## 4. Why This Task Exists

This is the single source of truth every other backend track imports. Divergent hand-rolled types anywhere else would silently break the contracts DOC3 defines.

## 5. Dependencies

none

- DOC3 §1.13 (ID uniqueness scopes)

## 7. Inputs

## 8. Expected Outputs

- One importable pydantic model per DOC3 §1 type

## 10. Exact Interfaces/Contracts to Follow

- RawRecord (§1.1)
- AdapterDescriptor (§1.2)
- EntityMention, RelationshipMention (§1.3)
- CanonicalEntity — entity_type excludes "Case", includes "Transaction" (§1.4)
- Relationship (§1.5)
- Evidence (§1.6)
- ResolutionDecision — includes source_record_ids (§1.7)
- Finding (§1.8)
- Case, Note, EdgeRef (§1.9-1.11)
- AnalyticsResult (§1.12)

## 11. Implementation Requirements

- Field names/types/nullability must match DOC3 §1 exactly — no extra fields, no renamed fields, no omitted fields.
- Use Literal[...] types for every closed enum (entity_type, relationship_type, extraction_method, etc.).
- CanonicalEntity.entity_type and EntityMention.entity_type must NOT include "Case" (DOC3 Round 2 correction, Contract Invariant 16) and MUST include "Transaction".
- ResolutionDecision must include source_record_ids as a parallel array to mention_ids (DOC3 §1.7).

## 12. Acceptance Criteria

- Every model is importable and instantiable with example data drawn directly from DOC3 §1.
- A field-by-field review against DOC3 §1 confirms an exact match (this is checked again automatically by H5's drift check later, but must be correct here first).

## 13. Tests Required

- Schema validation tests: instantiate each model with a valid example and confirm no validation error.
- A negative test confirming CanonicalEntity/EntityMention reject "Case" as an entity_type value.

## 14. Definition of Done

The full type set exists, imports cleanly, and matches DOC3 §1 field-for-field.
