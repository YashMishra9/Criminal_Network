## 1. Task ID and Title

**A2 — Config & Environment Loading**

## 2. Track

Track A (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement configuration loading for LIVE_ADAPTER_ENABLED, default dataset, Neo4j connection details, and LLM provider settings.

## 4. Why This Task Exists

Every track needs configuration without hardcoding values; this is also the single place that controls whether the live adapter runs at all (DOC2 §6.5 dataset isolation mechanism).

## 5. Dependencies

none

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC2 §15 (deployment/configuration)
- DOC3 §2.1 (dataset identifiers)
- DOC3 §2.6 (dataset isolation rules)

## 7. Inputs

- Environment variables: LIVE_ADAPTER_ENABLED, NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD, LLM_PROVIDER, LLM_API_KEY, DEFAULT_DATASET

## 8. Expected Outputs

- An importable Config object/singleton usable by every other backend module

## 9. Files/Modules to Create or Modify

- backend/app/config.py
- config/.env.example
- config/adapters.yaml

## 10. Exact Interfaces/Contracts to Follow

- config/adapters.yaml entries must match the AdapterDescriptor shape (DOC3 §1.2) exactly: adapter_id, source_type, dataset, mode, enabled, poll_interval_seconds

## 11. Implementation Requirements

- Use a settings library (e.g., pydantic BaseSettings) for typed, validated env loading.
- DEFAULT_DATASET defaults to "synthetic_demo" per DOC3 §2.3/§2.6.
- LIVE_ADAPTER_ENABLED defaults to false.
- Fail fast with a clear error message if a required variable is missing outside of local-dev mode.
- config/.env.example must document every variable with a comment.

## 12. Acceptance Criteria

- Importing config with only .env.example's defaults set produces a valid Config with LIVE_ADAPTER_ENABLED=false and DEFAULT_DATASET='synthetic_demo'.
- Overriding any variable via the environment is reflected correctly.

## 13. Tests Required

- Unit tests for default values.
- Unit tests for environment-variable override behavior.
- A test asserting missing required vars raise a clear error outside dev mode.

## 14. Definition of Done

Config is loadable from .env.example without error and produces the documented defaults.

## 15. Parallelization Information

## 16. Integration / Sync Point

Contributes to Sync 1 (A-ready).

## 17. Explicit Constraints — Things This Task Must NOT Do

- Do not hardcode secrets anywhere.
- Do not add configuration options beyond what DOC2/DOC3 require (dataset default, adapter enablement, Neo4j connection, LLM provider settings).
