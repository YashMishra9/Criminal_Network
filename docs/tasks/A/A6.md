## 1. Task ID and Title

**A6 — Error Envelope & Exception Handling**

## 2. Track

Track A (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement the ErrorResponse envelope and global FastAPI exception handlers for all six DOC3 §13 error types.

## 4. Why This Task Exists

Consistent, contract-correct error responses are required across every endpoint; this must exist before any router does real work.

## 5. Dependencies

A1, A3

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §13 (Error Contracts, full — envelope shape and the six-row status/type table)

## 7. Inputs

- DOC3 §13 ErrorResponse shape and status-code table

## 8. Expected Outputs

- Global exception handlers producing correctly-typed ErrorResponse bodies

## 9. Files/Modules to Create or Modify

- backend/app/contracts/errors.py
- backend/app/main.py (handler registration)

## 10. Exact Interfaces/Contracts to Follow

- ErrorResponse { error: { type: 'not_found'|'validation_error'|'llm_unavailable'|'dataset_isolation_violation'|'graph_unavailable'|'internal_error', message: string, details: object|null } }
- Status mapping: not_found->404, validation_error->400, llm_unavailable->503, dataset_isolation_violation->400, graph_unavailable->503, internal_error->500

## 11. Implementation Requirements

- Implement one exception class + handler per error type, each producing the exact envelope shape and status code from the DOC3 §13 table.
- Ensure no endpoint can return HTTP 200 with silently-omitted data on internal failure (DOC3 §13 rule) — a failed sub-operation must always surface as one of these six typed errors.

## 12. Acceptance Criteria

- Raising each of the six typed exceptions from a test route produces the correct status code and envelope body.

## 13. Tests Required

- One unit test per error type confirming status code + body shape.

## 14. Definition of Done

All six error types produce a correct envelope and are wired into A1's app via global exception handlers.

## 15. Parallelization Information

Depends on A1 and A3; otherwise parallel with A2, A4, A5.

## 16. Integration / Sync Point

Contributes to Sync 1.

## 17. Explicit Constraints — Things This Task Must NOT Do

- Do not invent error types beyond the six DOC3 §13 defines.
- Do not allow any endpoint to return a 200 with silently-omitted or partial data — a failed required sub-operation is always a non-2xx response.
