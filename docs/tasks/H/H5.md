## 1. Task ID and Title

**H5 — Contract-Drift Check (Frontend/Backend Type Sync)**

## 2. Track

Track H (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement a check that fails if frontend/lib/types.ts diverges from backend/app/contracts/*.py (and, transitively, DOC3 §1).

## 4. Why This Task Exists

DOC4 §2 flags this as a real risk — hand-kept types on both sides can silently drift without an explicit guard.

## 5. Dependencies

A3, E1

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC4 §2 (repository structure note on shared contracts)

## 7. Inputs

- backend/app/contracts/*.py, frontend/lib/types.ts

## 8. Expected Outputs

- A CI-runnable drift-check script or test

## 9. Files/Modules to Create or Modify

- scripts/ (drift-check script) or a backend/tests/contract/ entry

## 10. Exact Interfaces/Contracts to Follow

- None new.

## 11. Implementation Requirements

- Compare the field sets/types of the two type definitions and fail clearly on any mismatch.

## 12. Acceptance Criteria

- An intentionally introduced mismatch (test the checker itself) is caught by the check.

## 13. Tests Required

- A test that deliberately desyncs the two type sets and confirms the checker fails as expected.

## 14. Definition of Done

The check is wired into CI, or at minimum runnable on demand by any contributor.
