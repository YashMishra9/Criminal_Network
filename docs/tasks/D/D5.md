## 2. Track

Track D (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement GET /analytics, GET /analytics/shortest-path, and GET /patterns per
DOC3 §12.5-12.6.

## 4. Why This Task Exists

Exposes D1-D4 to the frontend (E4).

## 5. Dependencies

D4

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §12.5-12.6 (exact request/response shapes)

## 7. Inputs

- Query parameters per each endpoint's documented signature

## 8. Expected Outputs

- GET /analytics returns `AnalyticsResult` for centrality/community algorithms.
- GET /analytics/shortest-path returns the existing `ShortestPathResult` model.
- GET /patterns returns `{findings: Finding[]}` from persisted Finding nodes.

## 9. Files/Modules to Create or Modify

- backend/app/api/analytics.py
- backend/app/api/patterns.py

## 10. Exact Interfaces/Contracts to Follow

- `GET /analytics?dataset=&as_of=&algorithms=` -> `AnalyticsResult`. Supported
	algorithms are `degree`, `betweenness`, `pagerank`, and `community`; if
	`algorithms` is omitted, all four are requested. `shortest_path` is not
	accepted by this endpoint.
- `GET /analytics/shortest-path?dataset=&as_of=&shortest_path_from=&shortest_path_to=`
	-> `ShortestPathResult`. `shortest_path_from` and `shortest_path_to` are
	required entity ID strings matching the D1 `AnalyticsRequest` fields.
- Both analytics endpoints default `dataset` to `synthetic_demo` and apply
	C5's shared `as_of` semantics.
- `GET /patterns?dataset=&as_of=` -> `{findings: Finding[]}`.

## 11. Implementation Requirements

- GET /analytics and GET /analytics/shortest-path must reuse D1 and the existing
	graph snapshot interface; do not reimplement analytics algorithms.
- GET /patterns reads persisted Finding nodes filtered by subject visibility at
	`as_of` (§2.4A) — it must NOT trigger a new detection run (DOC3 Round 2
	correction).

## 12. Acceptance Criteria

- All three endpoint response shapes match DOC3 §12.5-12.6 exactly.
- Shortest-path query parameters and response use the existing D1/DOC3 models.
- Confirm GET /patterns has no side effect of triggering pattern detection.

## 13. Tests Required

- API integration tests, including a test that calling GET /patterns twice does not create new Findings.

## 14. Definition of Done

All three endpoints are functional. `/analytics` and `/patterns` match the E4
client contracts; `/analytics/shortest-path` exposes D1's path result contract.
