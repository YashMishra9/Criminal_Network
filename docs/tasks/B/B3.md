## 1. Task ID and Title

**B3 — Public/Live Adapter (optional capability)**

## 2. Track

Track B (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement poll() against one chosen public/open source (e.g., an RSS/news feed), with cursor handling and silent-failure behavior, tagged dataset='live_public'.

## 4. Why This Task Exists

Demonstrates the source-adapter extensibility DOC1/DOC2 committed to, without ever becoming a demo dependency.

## 5. Dependencies

B1

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §3 (poll() error-behavior rule)
- DOC2 §6.3 (live adapter silent-failure design)
- DOC1 NFR6 (only public/open, non-private data)

## 7. Inputs

- Configuration for the chosen public source (endpoint/feed URL)

## 8. Expected Outputs

- RawRecord[] via poll(cursor), tagged dataset='live_public'

## 9. Files/Modules to Create or Modify

- backend/app/ingestion/live_public_adapter.py

## 10. Exact Interfaces/Contracts to Follow

- SourceAdapter.poll(cursor: string|null) -> {records: RawRecord[], next_cursor: string}

## 11. Implementation Requirements

- poll() must catch ALL network/parsing errors internally and return {records: [], next_cursor: <unchanged>} — it must never raise.
- Update the adapter's own AdapterDescriptor.last_run_status/last_error on every call, success or failure.
- Only pull from public, ToS-compliant sources concerning organizations/public figures — never private individuals (DOC1 NFR6).

## 12. Acceptance Criteria

- A simulated network failure returns an empty result set, not an exception.
- AdapterDescriptor status updates correctly on both success and failure.

## 13. Tests Required

- Unit tests mocking network failure and success scenarios.
- A test confirming no exception ever escapes poll().

## 14. Definition of Done

Adapter is functional but entirely optional — the system runs correctly with LIVE_ADAPTER_ENABLED=false.

## 15. Parallelization Information

Parallel with B2 and the entire Track C.

## 16. Integration / Sync Point

Not required for Sync 2 (this is the optional capability).

## 17. Explicit Constraints — Things This Task Must NOT Do

- Must never become a hard dependency of the core demo (Contract Invariant 7).
- No new polling infrastructure — a simple scheduled task within the existing backend process only (DOC2 §6.4), no message queue or worker service.
