## 1. Task ID and Title

**B6 — LLM-Assisted Extraction**

## 2. Track

Track B (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement the LLM fallback path for genuinely ambiguous mentions, invoked only after B5's spaCy/regex extraction has run.

## 4. Why This Task Exists

Improves extraction quality on ambiguous free text without making extraction dependent on LLM availability.

## 5. Dependencies

B5, A5

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §4 ('LLM use' clause)
- DOC2 §7 (Entity Extraction Architecture)
- DOC2 §12A (LLM degradation model)

## 7. Inputs

- RawRecord + B5's partial (spaCy/regex) results for that record

## 8. Expected Outputs

- Additional EntityMention[]/RelationshipMention[] with extraction_method='llm'

## 9. Files/Modules to Create or Modify

- backend/app/extraction/llm_extractor.py
- backend/app/extraction/extractor.py (LLM-step wiring)

## 10. Exact Interfaces/Contracts to Follow

- Uses A5's LLMClient.generate(). On {status: 'unavailable'}, skip the LLM step for that record and proceed with spaCy/regex-only results.

## 11. Implementation Requirements

- Only invoke the LLM for cases B5 could not confidently resolve — attempt spaCy/regex first, always.
- Must handle an unavailable LLMResult by degrading gracefully for that record, never failing the whole record/pipeline.

## 12. Acceptance Criteria

- With the LLM forced unavailable (via test double), extraction still completes for all records using only B5's results.

## 13. Tests Required

- Unit test simulating LLMClient returning {status: 'unavailable'} and confirming the pipeline still completes.

## 14. Definition of Done

Full extraction pipeline (B5+B6) degrades gracefully when the LLM is down.

## 15. Parallelization Information

Depends on B5 and A5; proceeds in parallel with Track C.

## 16. Integration / Sync Point

Feeds Sync 2.

## 17. Explicit Constraints — Things This Task Must NOT Do

- Extraction as a whole must never become dependent on LLM availability (Contract Invariant 4).
