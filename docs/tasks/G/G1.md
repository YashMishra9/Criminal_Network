## 1. Task ID and Title

**G1 — CaseWorkspace Core (Case/Note/EdgeRef Associations)**

## 2. Track

Track G (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement create_case, add_entity/remove_entity, add_relationship/remove_relationship, add_evidence, add_note, with full dataset-isolation enforcement.

## 4. Why This Task Exists

Core case-building workflow (DOC1 W6); this is also where Contract Invariants 11 and 12 must be enforced.

## 5. Dependencies

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §6.5 (EdgeRef reuse rule)
- DOC3 §15 Invariants 11 and 12

## 7. Inputs

- Case/entity/relationship/evidence/note association operations

## 8. Expected Outputs

- A CaseWorkspace implementation (minus summary generation, see G2)

## 9. Files/Modules to Create or Modify

- backend/app/cases/workspace.py

## 10. Exact Interfaces/Contracts to Follow

- create_case(title, dataset) -> Case
- add_entity/remove_entity(case_id, entity_id)
- add_relationship(case_id, relationship_id) -> EdgeRef  (looks up the existing EdgeRef, never creates one)
- remove_relationship(case_id, edge_ref_id)
- add_evidence(case_id, evidence_id)
- add_note(case_id, text, about?) -> Note

## 11. Implementation Requirements

- add_relationship() must look up the existing EdgeRef by relationship_id and MUST NOT create a new one under any circumstance (Contract Invariant 12).
- Every association method must check that the item's dataset matches the case's dataset, rejecting with dataset_isolation_violation on mismatch (Contract Invariant 11).
- Note has no independent dataset field — it inherits the case's dataset by construction; if `about` is given, that target must also match the case's dataset.

## 12. Acceptance Criteria

- An explicit test confirming a cross-dataset association attempt is rejected with dataset_isolation_violation.
- An explicit test confirming add_relationship() never creates a duplicate EdgeRef for a relationship that already has one.

## 13. Tests Required

- Unit/integration tests for both acceptance criteria above, plus normal-path CRUD for every interface method.

## 14. Definition of Done

Both G-track Definition-of-Done criteria from DOC4 (dataset isolation, EdgeRef reuse) are met and tested.

## 15. Parallelization Information

Depends on C2/C3/C4 (post-Sync 2); proceeds in parallel with Track D and Track F.

## 16. Integration / Sync Point

Sync 2/3.

## 17. Explicit Constraints — Things This Task Must NOT Do

- Never create a second EdgeRef for an existing relationship.
- Never allow a cross-dataset association to succeed.
