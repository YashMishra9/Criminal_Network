## 1. Task ID and Title

**C3 — Graph Write Layer — Evidence & ResolutionDecision**

## 2. Track

Track C (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement write_evidence() (idempotent per source_id+dataset) and write_resolution_decision() (creating RESOLVED_FROM and BASED_ON edges).

## 4. Why This Task Exists

This is the mechanism that makes the exact entity-provenance path in DOC3 §2.5 actually queryable.

## 5. Dependencies

C2

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §1.6 (Evidence)
- DOC3 §1.7 (ResolutionDecision)
- DOC3 §2.5 (canonical entity provenance path, exact)
- DOC3 §6.2 (RESOLVED_FROM, BASED_ON)

## 7. Inputs

- Evidence data (derived from RawRecord via source_id)
- ResolutionDecision data (from B7/B8, including source_record_ids)

## 8. Expected Outputs

- write_evidence(evidence)
- write_resolution_decision(decision)

## 9. Files/Modules to Create or Modify

- backend/app/graph/write_layer.py

## 10. Exact Interfaces/Contracts to Follow

- write_evidence must look up an existing Evidence node by (source_id, dataset) before creating a new one — idempotent per DOC3 §1.13.
- write_resolution_decision creates CanonicalEntity-[:RESOLVED_FROM]->ResolutionDecision and ResolutionDecision-[:BASED_ON]->Evidence for every entry in source_record_ids.

## 11. Implementation Requirements

- Evidence writes must be idempotent: the same (source_id, dataset) pair always resolves to the same evidence_id.
- ResolutionDecision writes must correctly link the entity and every referenced Evidence node via the exact edges DOC3 §2.5 specifies.

## 12. Acceptance Criteria

- Calling write_evidence() twice for the same source_id+dataset yields exactly one Evidence node with a stable evidence_id.
- After writing a ResolutionDecision, the full CanonicalEntity->ResolutionDecision->Evidence chain is traversable.

## 13. Tests Required

- Integration test verifying Evidence idempotency across repeated writes.
- Integration test verifying correct RESOLVED_FROM/BASED_ON edge creation and traversal.

## 14. Definition of Done

The full provenance chain from DOC3 §2.5 is queryable end-to-end after seeding.
