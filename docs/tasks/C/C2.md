## 1. Task ID and Title

**C2 — Graph Write Layer — Entities & Relationships**

## 2. Track

Track C (see DOC4 §3 for the full track description and DOC4 §1 for where this track fits in the overall dependency structure).

## 3. Objective

Implement write_entity() and write_relationship(), where write_relationship() also creates the relationship's single EdgeRef and attaches evidence in one transaction, rejecting writes with no evidence.

## 4. Why This Task Exists

Central enforcement point for Contract Invariant 1 (no relationship without evidence) and Invariant 12 (exactly one EdgeRef per relationship).

## 5. Dependencies

C1

## 6. Relevant DOC1/DOC2/DOC3 Sections

- DOC3 §6.4 (required properties, corrected mechanism)
- DOC3 §6.5 (EdgeRef lifecycle, full)
- DOC3 §15 Invariants 1 and 12

## 7. Inputs

- CanonicalEntity objects; Relationship objects plus their supporting Evidence list

## 8. Expected Outputs

- write_entity(entity)
- write_relationship(relationship, evidence_list) — atomic: relationship + EdgeRef + SUPPORTS edges

## 9. Files/Modules to Create or Modify

- backend/app/graph/write_layer.py

## 10. Exact Interfaces/Contracts to Follow

- write_relationship must, in a single transaction: (1) write the domain relationship with relationship_id/dataset/valid_from, (2) create exactly one EdgeRef keyed by relationship_id, (3) create Evidence-SUPPORTS->EdgeRef edges from evidence_list. Reject (raise) if evidence_list is empty.

## 11. Implementation Requirements

- Single transaction per relationship write covering relationship + EdgeRef + SUPPORTS.
- Reject any relationship write with an empty evidence list — this is the actual enforcement point for Contract Invariant 1.
- Tag dataset on every node/relationship written, per DOC3 §6.7.

## 12. Acceptance Criteria

- Attempting to write a relationship with an empty evidence list is explicitly rejected (raises/returns an error) — must be tested directly.
- Writing the same relationship_id twice does not create a second EdgeRef.

## 13. Tests Required

- Unit/integration test: relationship write with evidence succeeds and produces exactly one EdgeRef.
- Unit/integration test: relationship write with empty evidence is rejected.
- Unit/integration test: re-writing an existing relationship_id does not duplicate its EdgeRef.

## 14. Definition of Done

Graph Write Layer demonstrably enforces Invariants 1 and 12.

## 15. Parallelization Information

Depends on C1; proceeds in parallel with all of Track B; C3 follows immediately after.

## 16. Integration / Sync Point

Contributes to Sync 2 readiness (verified by H3).

## 17. Explicit Constraints — Things This Task Must NOT Do

- Must not write a SUPPORTED_BY relationship type anywhere (retired per DOC3 §6.2/§6.4).
- Must never create more than one EdgeRef per relationship_id.
