## 10. Exact Interfaces/Contracts to Follow

- GET /entities/search?q=&dataset=&entity_type= -> {results: CanonicalEntity[]}
- GET /entities/{entity_id} -> {entity: CanonicalEntity, resolution: ResolutionDecision[]} or 404
- GET /entities/{entity_id}/relationships?dataset=&as_of= -> {relationships: (Relationship & {evidence: Evidence[]})[]}
- GET /graph?dataset=&as_of=&entity_types=&relationship_types=&community=&pattern= -> {entities: CanonicalEntity[], relationships: Relationship[]} (relationships carry evidence_ids only, not full evidence)

## 11. Implementation Requirements

- dataset query param defaults to 'synthetic_demo' when omitted, per DOC3 §2.6.
- as_of filtering must use C5's shared implementation exactly.
- /entities/{id}/relationships includes full inline Evidence[] per relationship; /graph includes only evidence_ids for performance — these are deliberately different per DOC3 §12.3 vs §12.4, not an inconsistency.
- All errors go through A6's ErrorResponse envelope.

## 12. Acceptance Criteria

- Each endpoint's response shape matches its DOC3 §12 definition exactly, field-for-field.
- GET /entities/{unknown_id} returns 404 per the DOC3 §13 table.

## 13. Tests Required

- API integration tests against a seeded graph (post-H3), covering the happy path and the 404 case.

## 14. Definition of Done

All four endpoints are functional and match DOC3 §12.1-12.4 exactly.
